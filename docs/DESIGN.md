# 設計說明（0.8.0）

給改規則、調數值的人看的；玩家看的說明在 [README.md](../README.md)。本文只寫**現行版本**，改了什麼、為什麼改放最後的〈版更歷史〉。兵種與建設用 0.8.0 起的原創顯示名，程式裡的 id 對照見 README〈種族與建設〉〈兵種〉；〈版更歷史〉保留當時的舊名。

## 想做成什麼

- **皇室戰爭的外形**：直式、3～5 分鐘一場、兩條路三座塔、拖卡片到戰場放兵就立刻出現、兵自己往前推。手機單手玩得動
- **星海爭霸的內裡**：資源不是自動回的能量，是礦工挖出來的；瓦斯要另外蓋；人口限制；科技樹解鎖兵種；輕甲／重甲剋制；範圍傷害、空中單位
- **核心取捨**：每一塊礦都是「現在出兵」或「投資經濟／科技」的選擇。早期爆礦工會被 rush，只出兵會被後期高階兵壓；這是皇室戰爭沒有、星海才有的張力
- **單機對電腦＋本機 server 的真人對戰**：見〈程式結構〉〈連線對戰〉

## 規則

### 戰場

22.5 × 30 格，1 格 = 24 px，畫布 540 × 960（上 720 戰場、下 240 面板）。玩家在下（y 小），電腦在上，所有座標對電腦鏡射（`Sim.mirror`）。

| 東西 | 位置（玩家側） | 數值 |
|---|---|---|
| 主堡 | (11.25, 2) | 血 1500、攻 13 / 0.75 秒、射程 7、打空陸 |
| 前哨塔 ×2 | (5.5, 6)、(17, 6) | 血 700、攻 10 / 0.75 秒、射程 6、打空陸 |
| 河 | y = 15 | 只是出兵範圍的界線：玩家放兵 y ≤ 14；單位行走不受河影響（橋是裝飾） |
| 路 | x = 5.5、17 | 單位依出兵點靠哪條路決定「自己的路」，沒目標時往該路的敵方前哨塔走，拆了就往主堡。路一律照畫面上的左右（x）算，電腦那邊鏡射後也一樣，所以兵是直直往前推 |

塔不吃火力強化，守門砲吃。塔血不回復。

### 單位行為（每步 0.05 秒）

1. 找目標：半徑 6 格內最近的、打得到的敵人（單位或建築）；塔與守門砲只看射程內
2. 有目標：在射程外就走過去，射程內就依冷卻開火；目標超出 7 格就重找
3. 沒目標：往「自己的路」的目標走
4. 傷害 = 攻擊 ×（1 + 0.1 × 升級等級）＋對應護甲的加成；範圍傷害對目標周圍的地面敵人造成一半；啾啾機打地面（含塔）只有一半
5. 同一步裡所有單位先開火、最後一起扣血：誰先被處理都不佔便宜，兩邊同時把對方打死就同歸於盡
6. 同層單位互相推開（地面對地面、空中對空中），地面單位也被建築推開，所以不會疊成一點

### 經濟

| | 數值 |
|---|---|
| 開局 | 礦 300、瓦斯 0、礦工 6、人口上限 12 |
| 礦收入 | 前 8 隻礦工各 +1.5/秒，第 9～16 隻各 +0.75/秒（飽和）；最多 16 隻 |
| 礦工 | 50 礦、8 秒、主堡一次一隻可排隊、佔 1 人口 |
| 抽氣站 | 75 礦、15 秒、每座 +2 瓦斯/秒、最多 2 座 |
| 貨櫃屋 | 100 礦、12 秒、人口 +8、上限 50 |
| 訓練營 | 150 礦、20 秒 |
| 組裝廠 | 150 礦 / 75 瓦斯、25 秒、需訓練營 |
| 機庫 | 150 礦 / 75 瓦斯、25 秒、需組裝廠 |
| 火力強化 | 100 礦 / 75 瓦斯、25 秒、一次一級、最多 3 級、需訓練營 |

建設同時蓋沒有上限（只有礦工一次一隻、升級一次一級）。電腦的收入倍率依難度不同（0.7 / 1.0 / 1.25）。

### 勝負

- 主堡被拆立刻結束
- 4 分鐘到：拆塔數多的贏；相同就進 1 分鐘驟死戰，先拆一座塔的贏
- **最後 90 秒（2:30 起）與驟死戰，礦與瓦斯收入加倍**（皇室戰爭的雙倍聖水）：逼雙方把存的資源推出去，戰局在最後一段分出勝負
- 驟死戰也到時：剩餘塔血合計多的贏；差 1 以內算平手

### 兵種數值

見 [js/data.js](../js/data.js) 的 `UNITS`，README 有玩家看的版本。設計意圖：

- **豆丁兵**是基準：50 礦、10 DPS、45 血。所有兵的價值用「幾隻豆丁兵」衡量
- **重拳機**＝拆塔與打重甲，但打不到空中，所以不能全出
- **火花車**＝懲罰豆丁兵海，速度 4 可以快速換路救火
- **轟轟車**＝射程 7 超過前哨塔的 6，可以站在塔外面轟；範圍傷害半徑 1.2，剋成群的豆丁兵與火花車；代價是 125 瓦斯與怕空中
- **啾啾機**是空中單位、主力防空，功能是對付嗡嗡機；打地面只有一半傷害，不然地面三種兵都打不到它，會變成什麼都剋
- **嗡嗡機**＝高單體傷害、只有三種東西打得到，逼對手留豆丁兵
- **守門砲**是皇室戰爭式的防守卡：不佔人口、60 秒消失、最多 3 座，用來擋一波而不是永久據點

## 電腦對手（`js/ai.js`）

每 `think` 秒看一次局勢，產生和玩家一樣的指令。同一次思考的指令用一份預算（`res`）一起算，不然後面的指令會因前面花掉的資源失敗。

- **經濟**：人口剩 3 以內補貨櫃屋（最多兩座同時蓋）；礦工補到目標數（簡單 10、普通 12、困難 14），礦超過 500 再往 16 補；礦工 ≥ 6 蓋訓練營 → 抽氣站 → 礦工 ≥ 9 蓋組裝廠 → 第二座抽氣站 → 礦 > 250 蓋機庫；礦 > 300 且瓦斯 > 150 升級
- **守**：玩家的兵過了河、進到我方半場一格以上才算威脅（停在河邊互打的不算）。在威脅較多的那條路、前哨塔前面放兵，補到「我方在半場的兵價值 ≥ 威脅價值」為止、一次最多三隻；普通以上會依威脅挑剋制兵（有空中→豆丁兵、啾啾機；輕甲 ≥ 3→火花車；重甲 ≥ 2→重拳機、轟轟車）。那條路的前哨塔血剩一半以下補守門砲（最多 2 座）
- **攻**：礦存到一波的預算（簡單、普通 250，困難 300，每過 1 秒再加 0.5）就一次最多 12 隻全放在玩家前哨塔血較少的那條路、河邊；收入加倍那段與驟死戰門檻降到 150。瓦斯存到 150 以上就多出要瓦斯的兵
- 思考的起始時間帶隨機偏移，電腦對電腦時兩邊才不會每次都同一步思考、先手固定占便宜

**可重現的模擬**（連線對戰靠這個）：

- 模擬固定步長 0.05 秒，所有亂數走 `mulberry32(seed)`，同樣的種子與同樣的指令序列跑出一模一樣的結果
- 玩家與電腦的每個動作都是指令（`{type:'deploy', unit, x, y}`、`{type:'build', what}`），一律經 `Sim.applyCommand` 驗證；畫面與輸入不直接改狀態
- 模擬只用加減乘除、`Math.sqrt`、`Math.imul`（IEEE 規定結果唯一），不用三角函式與排序，所以不同瀏覽器、手機與 Node 跑出來逐位元相同。**改 sim.js 時要守住這條**；三角函式只能出現在 render.js

## 連線對戰

參考貪食蛇 server（partygo-server-snake）的做法：**server 權威、server 是時鐘、client 只送指令**；房間流程、resumeToken 重連、斷線電腦代打與中離判定照它的規則。

**和貪食蛇不同的地方**：貪食蛇的 server 是 Go，模擬要從 TS 移植一份、靠對拍守住兩份一致，所以每 tick 廣播整張快照，client 再做預測與回滾。這裡 server 直接用 Node 跑**同一份** `js/sim.js`，三邊算出來必定一樣，所以每 tick 只廣播「這一步要執行的指令」（多數 tick 是空的，一包幾十 byte）；快照只在重連與分岔修復時送。

**一步怎麼走**（server，`stepRoom`）：收集這一步的指令（電腦代打的先，真人的依到達順序）→ 依序 `applyCommand` → `Sim.step` → 廣播 `{type:'frame', tick, cmds:[[pid, cmd], …]}`。client 收到才照同樣順序執行同一串指令再走一步；**自己下的指令也不先執行**，送出後等 server 排進某一步（區網延遲約一步，0.05 秒）。指令被模擬拒絕（礦不夠等）時，兩邊同時算出同樣的拒絕，下指令的那邊跳提示。

| 項目 | 做法 |
|---|---|
| 傳輸 | WebSocket（`/ws`），JSON，`type` 欄位分流；server 跟網頁同一個 port |
| 時鐘 | server 依真實時間補足該走的步數（不累加 setInterval，不會越跑越慢）；client 依自己的時間一步一步吃，佇列超過 3 步就一次追到剩 1 步 |
| 席位 | 玩家 0／1 由 server 隨機分配；指令的 pid 由 server 依連線決定，不信 client 自報；一個玩家一步最多 8 個指令 |
| 視角 | 兩邊都畫「自己在下」：自己是玩家 1 時 `main.js` 把局面鏡射（x→w−x、y→h−y）、敵我對調後交給 Render；拖卡的座標反鏡射回模擬座標 |
| 分岔檢查 | 每 40 步（2 秒）client 送 `Sim.hash`（逐位元雜湊），和 server 那一步的雜湊不同就補一張快照（`resync`）並記 log |
| 心跳 | client 每秒 `ping`，server 回 `pong`（畫面左上角顯示延遲）；5 秒沒收到任何訊息當斷線 |
| 慢連線 | 送出緩衝積到 256 KB 就先停送那個人，通了再補一張快照（丟舊保新，不拖住房間） |

**開局序列**（順序是契約，重連時整套重送）：`join` → `queued` → 配到對手 → `joined {pid, token}` → `config {seed, races}` → `start {in, snap}` → `frame` × N → `result {tick, winner, reason}`。`start.in` 是倒數毫秒（3 秒）；`snap` 是重連時的目前狀態（`Sim.snapshot`），新局為 null。

**斷線**（數值與貪食蛇相同）：

- resumeToken（128 bit）存 sessionStorage，F5 會自動送 `resume` 連回原席位，server 回完整開局序列＋目前快照；同一個 token 的舊連線被踢掉
- 斷線 3 秒起 server 用普通難度的電腦代打（指令照樣廣播，對手畫面看得到「電腦代打中」）；連回就收回
- 15 秒沒連回判中離，對手獲勝；兩邊都斷 15 秒就關房。client 那邊連不上會每 1.5 秒重試，30 秒放棄
- 結束後房間留 60 秒，剛好斷線的人連回來還看得到結果

連線對戰的戰績另外記一欄（「連線」），不跟對電腦的混在一起。

## 重播

模擬可重現，所以重播只存開局參數與指令，不存畫面：`{v, date, mode, level, seed, income, races, me, cmds: [[第幾步, pid, 指令], …], end: {tick, winner, reason}}`，一場約 10 KB，localStorage 的 `starclash.replays` 留最近 20 場（存不下就丟最舊的）。

- **錄**：`main.js` 的 `apply()` 包住 `Sim.applyCommand`，每個指令記成「在第 `g.tick + 1` 步之前執行」。單機錄玩家與電腦的指令；連線錄 server 排好的指令（含對手與電腦代打的）。連線重連時中間那段沒收到，所以 server 在房間裡記整場的 `log`，`start` 訊息一併送，client 拿它當重播的開頭
- **放**：同樣的 seed、收入倍率、種族建局，每一步之前執行紀錄裡步數 ≤ 下一步的指令再 `Sim.step`。`end` 用來收尾 server 判的結束（中離），也是進度條的長度。拖進度條往回＝從頭重建再快轉（整場 4800 步，算一下就好）
- 從錄的那一方的視角看（`me`），自己是玩家 1 時一樣鏡射
- 驗證：無頭連線對戰（含一方斷線 5 秒由電腦代打再連回）結束後，兩方各自用錄到的指令重播，終局 `Sim.hash` 與實際那一場相同
- 數值改版後舊重播會跑出不同結果（存了 `v`，版本不同時提示）；不做版本相容

## 版更歷史

- **0.1.0**（2026-10-21）：第一版。無頭模擬調了三輪：原本塔血 1500 / 攻 18、礦工 4 隻起、瓦斯 0.8/秒、4 分鐘，電腦對電腦 30 場全部打到驟死戰結束、出不了重工廠以上的兵；改成現在的數值後困難打簡單 30 場全勝、半數在正規時間拆塔分勝負，同等級對打仍多數打到驟死戰（兩邊都反應式防守，這是對稱的電腦才會這樣，真人會主動換路）。原本電腦每次思考只放一隻兵，塔一隻隻吃掉；改成存到一波預算一次放
- **0.2.0**（2026-10-21）：美術全部重畫（程式畫的造型、地形、特效），數值沒動
- **0.3.0**（2026-10-21）：出兵改成拖卡片到自家半場，點一下卡片就放在自家半場的隨機位置
- **0.4.0**（2026-10-21）：平衡大改。改之前電腦對電腦 30 場全部打到驟死戰結束、沒有一場拆塔，追了一場的時間線找到三個原因：
  1. 電腦把停在河邊互打的兵也當成入侵，一直一隻一隻補兵「守」，礦永遠存不到一波；瓦斯也堆著不用（一場堆到 800 多）
  2. 電腦那邊的前哨塔 lane 是用鏡射前的索引，下方的兵會斜著走去對面那條路，上下兩邊的路線不對稱（同等級對打下方勝率約三分之二）
  3. 同一步裡先處理的單位先開火、對方來不及還手
  修法：威脅改成過河一格以上才算、守只補到跟威脅等值、瓦斯多就出瓦斯兵、一波的預算隨時間變大；lane 一律照畫面左右；傷害改成同一步一起結算。再加上最後 90 秒收入加倍、正規時間 5 分鐘改 4 分鐘、礦收入 ×1.5、塔變弱（前哨塔 1000→700 血、攻 14→10、射程 6.5→6；主堡 2000→1500 血、攻 18→13）。兵種用 `tools/duel.js` 看同價對打：坦克原本連陸戰隊都打不贏，改成攻 30、冷卻 1.6、範圍 1.2、血 200；惡火對輕甲加成 6→10（才剋得了陸戰隊）；掠奪者血 125→150；維京打地面只剩一半。
